# Story 14.3 filtered smoke dataset repin — Requirements (BA)

## Summary

The original pinned smoke dataset
`/Volumes/Data NVME/datasets/anthropomorphic-frankenmerge/mlx-4096`
failed preflight because `train.jsonl` line 56 was approximately 8,520 tokens,
exceeding the 4096 max-seq-length bound. The operator authorized and created a
separate filtered copy at
`/Volumes/Data NVME/datasets/anthropomorphic-frankenmerge/mlx-4096-smoke`
with the same train/valid/test filenames; 66 rows excluded using the smoke
preflight fallback; all remaining rows pass the <=4096 fallback bound. The
original dataset is untouched and remains immutable.

This slice repins the bounded real-smoke contract from the original dataset
path to the filtered copy, preserving all other pinned parameters exactly.

## User story

As a DS4 fine-tuning operator (WHO), I want the bounded real-smoke contract
repinned from the original dataset path to the pre-filtered
`mlx-4096-smoke` copy so every row passes the <=4096 token bound (WHAT), so
that the single authorized Phase 2 real-model smoke can execute preflight
without aborting on a long row and prove the segmented provider runs
forward/backward against real 4096-token data through the trainer-owned
pipeline (WHY).

## Derivation-of-parameters provenance

The filtered dataset is a derived execution fixture, not a new training
source. Its provenance chain is:

  Original dataset (immutable)  →  smoke preflight fallback filter  →  filtered copy

- The filter used the same conservative whitespace-token bound at 4096 that the
  smoke preflight uses when no tokenizer is available, ensuring consistency
  between dataset creation and runtime validation.
- 66 rows that exceeded the bound were excluded.
- All remaining rows in train, valid, and test splits pass the <=4096 fallback
  bound.
- The original dataset is not referenced by the smoke entry point after the
  repin.
- The filtered copy retains the same file schema (`{"prompt": ..., "completion": ...}`)
  and the same split filenames.
